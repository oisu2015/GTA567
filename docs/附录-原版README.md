# 致强视频（DuSheNative）v2.2

基于 **TVBox 接口规范** 的**原生**影视客户端，专为老电视 / 盒子（Android 4.1~4.4，含 1G 内存设备）打造。
彻底不用 WebView——UI 与播放器全是原生渲染，内存占用低一个数量级，在老盒子上稳定。

> 原名「读舍TV·原生」，v2.2 更名「七微TV」，现更名 **致强视频**（仅显示名变更，包名 `com.dushetv.box` 不变以保证覆盖升级）。

## v2.2 更新（本次——更名 + 修闪退根因）

### 1. 软件更名：读舍TV·原生 → 七微TV
应用显示名、标题栏、README 全部改为「七微TV」。包名保持不变，可直接覆盖旧版升级。

### 2. 修复首页闪退（这才是「测试之后崩溃」的真凶）
v2.0/v2.1 在模拟器上「加载首页后闪退」，根因不是测速，而是 **`item_grid.xml` 里 ImageView
误写成 `android:height="130dp"`**（正确属性是 `android:layout_height`）。缺少 `layout_height`
会让 GridView 渲染首张卡片时抛 `RuntimeException: You must supply a layout_height` 直接闪退。
已改为 `android:layout_height="130dp"`，并给 `GridAdapter.getView` 加了 try/catch 兜底
（单条脏数据只返回空占位卡，不会拖垮整页）。

### 1. 开机首页秒开，不再被测速卡住
v2.0 首次启动会**阻塞在 41 个源的测速对话框上约 50 秒**才进首页，实测很慢。
v2.1 改为：**默认立即打开第一个直连源「非凡」秒进首页**；测速放到**后台静默**进行。
- 后台测完，若发现比当前更快的直连源 → 弹「是否切换」提示（可保持当前）；
- 当前即最快（非凡仍是第一）→ **不打扰、保持**；
- 选定过的源会被记住，下次开机**直接秒开**，不再测速。

### 2. 测速 / 切源全流程崩溃兜底

`applySpeedItem`、`promptSwitch`、`showApiSpeedResult` 全部加 `try/catch` 与 `isFinishing()`
守卫，异常只弹 Toast 不会闪退；弹窗前检查页面是否已销毁，杜绝 `BadTokenException`。

## v1.7 更新（上版——首页改版：只要热播电影 / 热播电视剧）

v1.6 首页直接展示接口推荐流，而推荐流里短剧占大多数，电视上看短剧体验很差。
按真实使用习惯重做了首页与分类：

1. **首页只放「热播电影」+「热播电视剧」**
   不再用接口推荐流，改为拉取「电影」「电视剧」两类内容混合，按评分+热度排序。
   加载时额外过滤片名含「短剧」的残留项，保证首页一个短剧 / 动漫都没有。
2. **短剧、动漫统一归「其他」**
   分类归并规则调整：短剧不再进「电视剧」、「动漫」不再作为独立大类，二者一律归入「其他」。
   分类导航条变为：**电影 / 电视剧 / 综艺 / 纪录片 / 其他**。
3. **「其他」可找回短剧 / 动漫**
   点「其他」会合并展示所有被归并的分类（短剧、动漫等），想看仍可在此进入。

## v1.6 更新（本次——修 v1.5「黑屏且无任何提示」）

v1.5 集成了 ExoPlayer，但真机实测仍是黑屏、不报错。定位到三个叠加的硬伤，全部修掉：

1. **监听器注册时序错误（黑屏无提示的直接原因）**
   v1.5 在 `prepare()` 之后才 `addListener`，ExoPlayer 早期派发的 `BUFFERING` / `ERROR` 事件
   全部落空——播放失败时界面上什么都不会变，看起来就是"卡在黑屏、连错误都不弹"。
   v1.6 改为 `build()` 后**立即注册监听**，再 `setMediaSource` → `prepare`。
2. **ExoPlayer 绕开了 TLS 放宽策略**
   `Net.java` 里为老盒子写的 TLS1.2 放宽 + 证书宽松校验，只作用于 App 自己的请求；
   ExoPlayer 的 `DefaultHttpDataSource` 内部另开 `HttpURLConnection`，在 Android 4.4 上
   对现代 HTTPS 源**直接握手失败**。v1.6 新增 `Net.installGlobalTls()`，把宽松 TLS 装成
   JVM 全局默认，播放器网络请求与 App 共用同一套策略。
3. **拒绝跨协议重定向**
   大量 m3u8 会在 http / https 之间 302，ExoPlayer 默认不跟随，直接判为 source error。
   v1.6 开启 `allowCrossProtocolRedirects`，并把连接/读取超时放宽到 15s。

配套新增的排障能力：

- **屏幕诊断 HUD**：播放页左上角实时打印设备信息、地址、HTTP 状态码、m3u8 分片数、
  视频/音频编码与分辨率、错误全文。真机出问题时不用连电脑看日志，屏幕上就能看到卡在哪一环。
- **链路预检**：与播放并行拉取前 1KB，立刻分清「网络到不了」还是「拿得到但解不了」；
  若返回的是网页而非视频，会直接提示该线路已失效或需要解析。
- **双引擎自动回退**：ExoPlayer 失败自动切系统 MediaPlayer 重试，左右方向键可手动切换。
- **内置测试片自检**：播放页按 `0` 播放标准 HLS 测试流，一秒区分「播放器坏」还是「线路坏」。
- **按键**：确定=暂停/播放，←→=切引擎，`0`=测试片，MENU/INFO=显隐信息，返回=退出。

产物：`dushenative-tv-v1.6.apk`（约 1.55MB，versionCode 7，V1+V2 签名）

## v1.5 更新（上一版——基于真机 CM101S-2 + 影视仓参考）

1. **内置 ExoPlayer 2.14.2 播放引擎（关键修复：真机不能播）**
   真机（CM101S-2 / 4.4.2）原生 MediaPlayer **不支持 m3u8(HLS)**，所以之前在模拟器能看、上电视就黑屏。
   v1.5 把 ExoPlayer 作为自带运行环境打包进 APK，**软/硬解都走 ExoPlayer**，m3u8/HLS 在老盒子上也能直接播。
   播放器已是标准 Maven 依赖（`com.google.android.exoplayer:exoplayer-core:2.14.2` + `exoplayer-hls:2.14.2`），
   不再依赖一堆手工收集、易损坏的本地 AAR。
2. **UI 美化（针对 1280×720 电视）**
   - 操作按钮（搜索 / 切换源 / 测速选最快 / 换接口）**紧跟在"软件名 + 源名"标题之后**，一行内联，不再另占一行。
   - 按钮改为**深色背景 + 立体描边字**（白字 + 黑色阴影），解决之前白底白字看不清的问题。
   - 整屏加 **10dp（≈20px）内边距**，避开电视过扫（overscan），不再"大出电视一圈"。
   - 标题栏深色、分类条与内容区分层清晰，整体更"大气"。
3. **保持 v1.4 的体验**
   m3u8 线路默认优先、标准六类导航、首页评分+热度排序、操作按钮栏不变。

## v1.4 更新（上一版——基于 MuMu 模拟器实测反馈）

1. **默认播放线路改为 m3u8 优先**
   实测发现「feifan」等线路会提示下载且无法播放，而「ffm3u8」线路速度好、直接能播。
   现在进入详情页时**自动选中包含 m3u8 的线路**作为默认，不再需要手动切换。
2. **主界面新增操作按钮栏**
   标题下方固定显示一行按钮：**搜索 / 切换源 / 测速选最快 / 换接口**。
   选源后不再"迷路"，随时可以搜索、切换视频源、重新测速或更换接口——不依赖 MENU 菜单键。
3. **分类导航标准化**
   API 返回的原始分类（剧情片/动作片/国产剧/港台剧/真人秀…）太杂太多。
   现在自动归并为 **6 个标准大类**：**首页 / 电影 / 电视剧 / 综艺 / 动漫 / 纪录片 / 其他**，
   不再是一条长到看不完的分类条。点分类仍用原始 tid 请求，数据准确。
4. **首页按评分+热度综合排序**
   不再简单按 API 默认顺序（通常是更新时间/播放量），改为：
   **评分高的排前面 → 评分相同则热度（播放量）高的排前面 → 无评分的排最后**。
   首页展示的是真正值得看的内容，而不是最新更新的。

## 使用步骤

1. 安装 `dushenative-tv-v1.5.apk`，首次启动自动弹配置框。
2. **推荐直接点「一键测速·自动选最快」**——测完自动进最快的源，不用挑。
3. 主界面顶部有操作按钮栏：**搜索 / 切换源 / 测速选最快 / 换接口**，随时可用。
4. 分类条已标准化为：首页 / 电影 / 电视剧 / 综艺 / 动漫 / 纪录片 / 其他。
5. 详情页自动选中 m3u8 线路，OK 即播。

## 支持什么

- **接口配置**：TVBox 格式 `{"sites":[...]}` 或 `{"video":{"sites":[...]}}`（带注释也能解析）。
- **站点类型**：
  - ✅ `type=1`（JSON / 苹果CMS）：完整支持。
  - ⚠️ `type=0`（XML）：明确提示不支持。
  - ❌ `type=3`（JS 爬虫 spider）：v1 不支持，v2 计划内嵌 Rhino。
- **播放**：内置 **ExoPlayer 2.14.2** 引擎（自带软/硬解），`SimpleExoPlayer` + `HlsMediaSource`(m3u8/HLS) / `ProgressiveMediaSource`(常规)；不再受盒子的 MediaPlayer 能力限制。
- **遥控器**：方向键导航 + OK 操作，返回上层/退出。

## 已知限制（v1）

- type=3 接口需 v2（Rhino JS 引擎）
- 公开源随时间失效，失效就重新测速换一个
- 极端情况下个别 HTTPS 流仍可能失败，可换线路重试

## 工程

- `app/src/main/java/com/dushetv/box/`
  `Net`（TLS 网络 + URL 规范化 + 测速探针）、`SpeedTest`（并发测速/排序）、
  `ApiConfig`（配置解析 + JSON 清洗）、`SiteApi`（type0/1 调用 + 评分排序）、`ImageLoader`（海报降采样 LRU）、
  `MainActivity`（浏览/导航/测速 UI + 操作按钮栏 + 标准分类）、`DetailActivity`（详情/分集/m3u8优先）、`PlayerActivity`（播放）。
- 构建：复用 DuSheTV `.buildtools`，`minSdk 16 / targetSdk 23 / V1+V2 签名`。
  ExoPlayer 以 Maven 依赖引入（`exoplayer-core` + `exoplayer-hls` 2.14.2），启用 `android.useAndroidX=true`。
- 产物：`DuSheNative/dushenative-tv-v1.5.apk`（约 1.6MB，versionCode 6）。
